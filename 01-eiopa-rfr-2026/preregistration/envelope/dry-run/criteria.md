# Dry run — its criteria, fixed before it runs

The operator: the author, on the machine of SPEC §4a, by `run.sh <A|B> dry-<n> --dry`, once per builder, builder A after its sign-in through the egress, builder B after its key typed at `run.sh`'s prompt (SPEC §5, §3b), with the dry-run brief (`dry-run/brief.md`) and a padding file in place of the text and the bundle — no part of the text and no input of the cases is mounted. The dry run's time limit: 15 minutes. Builder B's dry run runs the real run's settings, key for key — `model.compressionThreshold` 1.0 in both: its CLI compresses only once the previous request's prompt reaches the whole of the 1,048,576 tokens it counts for a model it holds no limit of its own for (`packages/core/src/core/tokenLimits.ts:20`, `:37`) — and the real run's spend cap, $55 a run, held by the egress, which prices each answer's use at its rates (SPEC §3b). Builder B's test of its route — `run.sh B test-<n> --test <model>` — is read against these criteria with its model in place of `gemini-4-argon`: the envelope's test, not the dry run (SPEC §7).

The run passes when its archive shows each of these, read in the order of SPEC §6 — the archive's sha256 checked first; then builder B's run's end by `run_end.py` (SPEC §6) — a run ended by the vendor's unavailability is restarted under a new id, as the preregistration's §8 says, and its restart read in its place — a run stopped by the spend cap or ended by the plan's limit is not restarted; then the two first checks below; then the launch print and the egress log, against these criteria and the spec item by item, the check recorded; then `DRYRUN.md`.

First — a run that fails either ends the reading there, and the route returns to the author:
- **The route serves its model at its setting:** builder A — every generation request asks for `gpt-6-astra` at `xhigh`, any other refused at the wire; each generation's stream read to its end or its cut on its `served` line (SPEC §3), none unread; the route names the model that served in each stream — its form, recorded at builder A's third dry run: the `model` of the stream's `response.created` and `response.completed` events (`response.incomplete` in place of the second where the stream ends so) —: every generation's stream names `gpt-6-astra` there, the second where the stream reaches it, and every other name an answer or an event carries — `openai-model` or `x-openai-model` in its headers or in an event's `response.headers` — is `gpt-6-astra` too; a stream that names no model, or a name of another model, a finding; the `safety_buffering` value on each `served` line by its kind (SPEC §3): absent or `false` — no buffering; an object, or a `response.metadata` of that type — a safety-buffering event —, each named with its `retry_model`, or where it names none with the faster model the answers' `x-codex-safety-buffering-faster-model` header names; any other kind named; no item «model rerouted» among the CLI's events; builder B — its first generation request is answered with status 200, not 404: a 404 ends the run at once, no fallback.
- **The stand-ins hold:** builder A — the sign-in's requests in the egress log under its phase, each on its route's sign-in paths; `run.sh`'s check after the sign-in, on the console — every token of the credential file a stand-in the vault holds, none a real token, none under `state/`, `logs/` or `work/`; builder B — `run.sh`'s check before the run (`vault_check.py key B`), on the console — one key in the vault, the builder's `GEMINI_API_KEY` its stand-in, no real key under `state/`, `logs/` or `work/`; each request on its route carrying the stand-in, the key put in its place by the egress — the log's swaps; both — the scan of the archive: no real token or key of the vault in any member, beside the egress's own counts; `vault/` removed.

Then:
1. **The image:** the launch print names the builder image's id recorded at its build, and the CLI's version (`codex --version` · `gemini --version`) equal to the pinned release.
2. **The configuration printed:** every field of the launch print (SPEC §5) present; every file mounted read-only into the builder with its sha256 — under `/in`; `/envelope/entry.sh`; under `/envelope/config/` the configuration's folder, builder A's model catalog among them; under `/ca` the run's CA certificate —, each of this folder's byte-equal to it; the configuration file byte-equal to this folder's. Builder B's spend cap: the print names it, $55 a run, and the egress's ready marker, `egress/addon-ready-run.json`, the same cap, the rates it prices by and its bound, 32,768 tokens (SPEC §3b). Builder B's experiments file: the print names `GEMINI_EXP` and the file — byte-equal to this folder's `gemini/experiments.json` — and reads its timeout as the CLI does: 600 s (SPEC §4.2).
3. **A refused domain:** `example.org` refused at the egress — a `connect … refused` line for `https://` and a `request … refused` line for `http://` in `egress.jsonl` — and the command's own failure in `DRYRUN.md` step 3.
4. **A refused write:** `/in/probe.txt` not created — «Read-only file system» in step 2's line.
5. **No credential:** no `~/.ssh`, no `~/.gitconfig`, no git configuration (step 4); the launch print's own check agrees; the names of the environment variables the agent's shell sees — recorded. What this guards: no credential and no certificate authority reaches the agent's commands — none of the names the launch print lists with KEY, TOKEN, SECRET or CERT in them, the container's credential and certificate-authority variables, `GEMINI_API_KEY`, `SSL_CERT_FILE`, `NODE_EXTRA_CA_CERTS` and `CODEX_CA_CERTIFICATE` among them — builder A by its shell environment policy, builder B by its redaction (SPEC §4); a name with KEY, TOKEN, SECRET or CERT in it that names neither — git's `GIT_CONFIG_KEY_0` to `GIT_CONFIG_KEY_6`, which builder B's CLI sets for its shell to switch off git's credential helper, monitor, hooks, SSH command, pager and editors (`packages/core/src/services/shellExecutionService.ts:610`–`627`) — is listed with its source, not a finding; a credential's or a CA variable's name among them is a finding, closed before the freeze; builder A's credential file and builder B's key variable, which the agent's commands can read (SPEC §8), hold stand-ins alone — the first checks.
6. **No server-side search or fetch:** no request in `egress.jsonl` declares a server-side tool of a denied kind, at any depth of a namespace, and none was refused for one or for a namespace the egress could not read; the CLI's events show no web search or page fetch (steps 5 and 6 answered «none»).
7. **No second agent:** no agent spawned in the CLI's events; no agent tool among the tools each request declares — no `spawn_agent` or other multi-agent tool for builder A, no `invoke_agent` for builder B (step 7 answered «none»).
8. **Every request read at the egress:** each allowed request to the API names the configured model — `gpt-6-astra` · `gemini-4-argon`; each generation request — builder A's to `/backend-api/codex/responses`, builder B's `generateContent` and `streamGenerateContent` — carries the configured setting — builder A `reasoning.effort` `xhigh`; builder B `thinkingConfig.thinkingLevel` `HIGH`, its internal requests among them — its compression's (criterion 9) and, should one run, a loop check's: the CLI's first from its 30th model turn (`packages/core/src/services/loopDetectionService.ts:42`, `:278`–`279`), to `loop-detection` and, at a confidence of 0.9 or more, `loop-detection-double-check` (`:65`–`66`), both routed to `gemini-4-argon` by the settings — a dry run of fewer model turns sends none, the launch print's settings then the routing's record; a generation sent again after a 200 with its body unchanged — the CLI's own retry of a stream it could not use, at most three more after 1, 2 and 4 s (`packages/core/src/core/geminiChat.ts:106`–`107`, `:764`) — listed beside the request it repeats, not as a turn of its own; every request that asks for no generation — a token endpoint's, builder A's account check, builder B's model list or entry, a count of tokens — listed apart with its purpose, each allowed by its route in its phase; none refused for another model; builder B's last `stream-json` event names `gemini-4-argon` alone — for a run the limit stops, which writes none, its `init` event and the session file's model turns. A request to another model, or another setting, is listed with its purpose, for the spec to close before the freeze. A generation whose answer's headers come later than 60 s is waited for — up to the experiments file's 600 s (SPEC §4.2) —, not cut and sent again: shown when one comes that late; a cut at 60 s is a finding.
8a. **HTTP only:** builder A's first request to `/backend-api/codex/responses` is a WebSocket upgrade refused with 426, and every later request to the API an HTTP request; the run goes on after the refusal. Builder B's requests are HTTP requests; a WebSocket upgrade refused for it is listed with its purpose.
9. **No compression before the limit:** builder B's settings carry `model.compressionThreshold` 1.0 — the printed configuration shows it —, and the egress log shows no compression of its history — no `generateContent` request without tools among its streamed generations — while step 8's two reads raise the previous request's prompt to about 95,000 tokens, past the 20,972 at which the first dry run, its threshold lowered to 0.02, compressed; the tool loop goes on, every generation answered 200 and its calls run; no response with status 400 from the API in `egress.jsonl`.
